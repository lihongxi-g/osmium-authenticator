# 隐私政策

*生效日期：2026 年 10 月 16 日 · 适用于 Osmium v2.5.6 及后续版本*

*本页为当前版本：发布在 osmium.im。当你在「关于」中打开本政策时，应用会读取它。*

Osmium 不收集、出售或用于广告分析个人数据。没有账号体系、注册、广告 SDK 或崩溃上报，也没有 Osmium 云端账号或同步服务器。除你主动开启版本检查外，应用在启动时不发起任何网络请求。

存储：验证器密钥、账户名、服务商、标签及标签颜色仅存储在本设备上，使用 Android Keystore 中不可导出的密钥进行 AES-256-GCM 加密。导出备份使用你的密码加密（PBKDF2-HMAC-SHA256，120,000 次迭代后 AES-256-GCM）。WebDAV 登录信息与自动备份密码在本机加密存储，受 Keystore 保护。若开启开发者模式的明文导出，导出的文件不加密：以可读形式包含全部密钥，仅靠你存放它的位置提供保护。

设备完整性：应用启动时会在本机进行完整性检测——启动初期的早期快照、系统 / 挂载 / 内核 / 启动状态 / 应用签名等多项检查及其交叉核验，以及硬件级密钥证明（TEE 证书链、已验证启动链与 boot hash）——后者使用内置于应用中的 Google 根证书、由 Google 官方验证器在本机完成验证。Root 管理器检测只向 Android 查询一份固定的、已知 Root 管理器包名清单，不会遍历你设备上安装的应用。以上检测全部在本机进行，不发起任何网络请求，结果不会被存储或上传——它们只显示在完整性页面；检测结果为「可疑」或「已失陷」时，每次打开应用会提醒一次。装有 Root 管理器应用只作为提示，不构成判定。检测详细日志默认关闭，只有你在开发者模式中开启后才会写入本机日志。开发者模式中可以隐藏该功能；隐藏后应用不再在启动时进行这些检测，也不再提醒。

证明吊销数据：应用内置一份构建时取得的 Google 证明吊销状态列表快照。当你在完整性页面点击刷新时，应用会从 https://android.googleapis.com/attestation/status 下载一份新副本并存入应用私有存储，仅在下载内容解析成功后才会替换旧数据。该请求不携带任何账户、验证器或设备数据；与任何 HTTP 请求一样，服务器能看到连接的基本信息（例如你的 IP 地址）。若刷新失败或网络阻断，旧数据继续沿用，密钥证明验证可完全离线进行。

导入：无论是 Google Authenticator 二维码迁移，还是从 Aegis、2FAS、Raivo OTP 的导出文件导入，全部在本机完成。所选文件只会读入内存用于生成导入预览，不会被复制、上传或发送到任何地方；只有你确认的条目才会写入加密库，其余数据随即丢弃。若备份文件中存在本应用无法忠实复现的验证码参数（位数或算法不在支持范围内），该文件会被整份拒绝，因此被损坏或被改动的文件不可能加入一个只会生成错误验证码的账户。

网络：应用仅在以下情形建立连接：① 法律文本——当你在「关于」中打开《用户协议》或《隐私政策》时，从 osmium.im 读取当前版本，最多每 10 分钟一次，并保留已读取的副本供离线查看；② 向 GitHub Releases API 发起版本检查——默认关闭、可在设置中开启，在你使用应用期间于后台进行（开启后包含启动时）；③ WebDAV——在你启用自动备份或手动备份时连接你配置的地址；④ 局域网快捷传输——传输页面打开期间连接另一台设备；⑤ 上文的吊销数据刷新——只在你手动点击时发起；⑥ 打开链接——把地址交给你的浏览器或应用商店。这些请求都不会携带你的账户、密钥或设备标识。

法律文本：当你在「关于」中打开《用户协议》或《隐私政策》时，应用会从 osmium.im 获取当前版本，确保你看到的是当前生效的文本。该请求不携带任何账户、验证器或设备数据。若获取失败，应用会显示失败提示并提供前往官网的链接，上次读取的副本仍可查看。

版本检查：在版本检查开启时，应用会请求 https://api.github.com/repos/lihongxi-g/osmium-authenticator/releases/latest，判断是否存在更新的版本。该请求只发送包含应用名称与版本的 User-Agent；不发送账户、验证器或设备数据，失败时静默处理。该检查默认关闭，也可以随时在设置中再次关闭。

局域网快捷传输：两端必须处于同一 Wi-Fi 网络，接收方只接受能证明屏幕上所显示 12 位配对码的发送方。握手过程中，两台设备会交换手机型号名称、安装应用时生成的随机标识（不源自任何硬件标识）以及下文所述的风险代码，这些内容都被绑定在加密会话中。在传输任何数据之前，每台设备都会在本机扫描自己的网络链路以提示风险：读取系统 ARP 表（/proc/net/arp）、当前 Wi-Fi 的安全类型与网络名称、是否配置了 HTTP 代理、是否有 VPN 处于活动状态，以及默认网关的硬件地址。只有得出的风险代码——绝不包括原始细节——会发送给另一台设备，并且必须双方都确认后才会发送或接收账户数据。若你拒绝某台设备，它会被记入一份保留 24 小时的拉黑名单，以加密形式存放在应用私有存储中。传输相关的任何内容都不会发送给开发者或任何服务器。

自动备份使用 Android 系统调度，可能被厂商省电策略推迟。备份会以加密文件写入你配置的 WebDAV 服务器或 Download/Osmium 目录（默认保留最近 5 份，最多可设 10 份，更旧的会自动清理）。你设定的时间按设备本地时区计算。相机扫码、二维码识别与生物识别由 Android 在本机处理；仅当传输页面打开时才会使用 Wi-Fi 状态与组播进行设备发现。WRITE_EXTERNAL_STORAGE 仅适用于 Android 8/9 上的自动备份。在 Android 17 及更高版本上，应用会在局域网传输、连接你自己网络中的 WebDAV 服务器、或向这类服务器自动备份之前，申请局域网权限（ACCESS_LOCAL_NETWORK，属于「附近的设备」权限组）；若你拒绝，这些功能将不可用，应用会提供前往系统设置的入口。

我们不向广告商、分析服务或 Osmium 云端共享数据。WebDAV 服务器会收到你上传的加密文件；预期接收设备会收到你主动传输的数据；GitHub 只收到公开版本查询；Google 的证明状态端点只在你手动刷新时收到一次公开吊销列表的请求；osmium.im 只提供应用读取的公开法律文本，不会向其发送任何用户数据。卸载或清除数据不会删除你保存在其他位置的副本。
