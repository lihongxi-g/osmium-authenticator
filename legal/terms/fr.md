## Vos responsabilités :

- Protégez vos secrets, vos PIN et vos mots de passe de sauvegarde. Les clés de chiffrement ne peuvent être récupérées ni par le développeur ni par des tiers ; personne ne peut restaurer un PIN oublié, un mot de passe de sauvegarde perdu ou des données d’application effacées.
- Conservez vos propres sauvegardes. Désinstaller l’application ou effacer ses données supprime définitivement les comptes et paramètres locaux. Les sauvegardes automatiques dépendent de la planification d’Android et du fabricant et peuvent être différées ou bloquées par les politiques d’économie d’énergie.
- N’importez que des fichiers de confiance. Osmium importe depuis les QR codes de transfert de Google Authenticator et depuis les fichiers d’export d’Aegis, de 2FAS et de Raivo OTP. Examinez chaque entrée de l’aperçu avant d’importer, confirmez que le fichier provient bien de l’authentificateur que vous comptez quitter, puis supprimez les fichiers d’export après utilisation — ils contiennent vos secrets en clair. Un fichier de sauvegarde dont les entrées utilisent des paramètres de code qu’Osmium ne peut pas reproduire fidèlement (une longueur de code ou un algorithme hors de l’ensemble pris en charge) est refusé en bloc plutôt qu’importé en partie.
- Vérifiez les données reçues. Le transfert LAN rapide exige que les deux appareils soient sur le même réseau Wi-Fi : l’appareil récepteur affiche un code d’association à 12 chiffres, et l’appareil expéditeur doit le saisir avant que quoi que ce soit soit transféré. Chaque appareil affiche ensuite les risques réseau qu’il a détectés — sur lui-même et sur l’autre appareil —, et rien n’est envoyé ni accepté tant que les deux côtés n’ont pas confirmé ; annuler la boîte de dialogue interrompt le transfert. Ne communiquez le code qu’à l’appareil depuis lequel vous envoyez et confirmez les entrées dans l’aperçu d’import. Les deux appareils doivent exécuter une version qui parle le même protocole de transfert.
- Le PIN d’autodestruction est irréversible. Gardez l’horloge de votre appareil exacte et respectez les lois applicables et les règles de réseau pour les serveurs et appareils que vous configurez.
- Versions d’aperçu. Le canal d’aperçu, facultatif, propose les versions que le développeur marque comme pre-release sur GitHub. Elles contiennent du code plus récent et moins testé et peuvent mal se comporter ; faites votre propre sauvegarde avant d’en installer une, et la version stable du même numéro vous sera proposée dès qu’elle existera.
- Appareils rootés. Lorsqu’Osmium détecte que l’appareil est rooté, il active de force ses protections (vérification à l’ouverture, blocage des captures d’écran, codes masqués) et désactive le transfert LAN rapide, la sauvegarde WebDAV, les sauvegardes automatiques, la configuration de l’autodestruction et l’import depuis des tiers. Ces restrictions ne peuvent être levées qu’en mode développeur. La détection de root s’exécute localement sur l’appareil et est effectuée au mieux.
- Rapport d’intégrité de l’appareil. Au démarrage, Osmium contrôle également l’intégrité de l’appareil localement : contrôles du système, des montages, du noyau, de l’état de démarrage et de la signature de l’application, recoupements entre ces contrôles, ainsi qu’une attestation de clé matérielle (chaîne de certificats TEE, chaîne de démarrage vérifié et boot hash) vérifiée sur cet appareil avec le vérificateur officiel de Google. Le rapport n’est affiché que sur votre appareil ; lorsque le résultat est suspect ou compromis, l’application vous le rappelle une fois par ouverture. La présence d’une application de gestion de root est considérée comme un indice, et non comme une preuve. Aucun contrôle logiciel n’est parfaitement fiable : lisez donc le rapport comme une indication sur votre appareil, et non comme une garantie. Le mode développeur peut masquer cette fonction ; une fois masquée, l’application n’effectue plus ces contrôles au démarrage et n’affiche plus le rappel.
- Mode développeur. Caché derrière sept tapes sur le nom de l’application dans « À propos » et protégé par une vérification d’identité, il peut lever les restrictions liées au root, masquer des entrées de paramètres, exporter votre coffre en clair et forcer le rechiffrement de la base de données locale. Il propose également un journal de détection détaillé facultatif — les contrôles d’intégrité n’écrivent aucun journal sauf si vous l’activez. Un export en clair contient tous vos secrets sans chiffrement — quiconque obtient le fichier peut lire tous les comptes. Vous utilisez le mode développeur à vos propres risques ; le développeur n’est pas responsable des pertes causées par celui-ci ou par les exports en clair.

Vous pouvez utiliser Osmium pour votre propre authentification à deux facteurs et pour les appareils que vous contrôlez ou que vous êtes autorisé à utiliser.

Osmium n’a aucun système de compte ni aucune synchronisation cloud ; toutes les fonctions d’import s’exécutent entièrement sur cet appareil. L’application n’effectue aucune requête réseau au démarrage, sauf si vous activez la vérification de version facultative. Sinon, elle ne se connecte que lorsque vous utilisez une fonction qui en a besoin : le serveur WebDAV que vous configurez, l’API GitHub Releases pour la vérification de version facultative (désactivée par défaut ; vous pouvez l’activer dans les paramètres), le site osmium.im pour lire les versions actuelles des présentes Conditions d’utilisation et de la Politique de confidentialité lorsque vous les ouvrez dans « À propos », la liste publique des statuts d’attestation de Google lorsque vous actualisez les données de révocation sur l’écran d’intégrité, ou l’autre appareil pendant un transfert LAN. Le transfert LAN utilise un chiffrement AES-256-GCM dérivé du code d’association et ne passe pas par un serveur cloud Osmium.

Les versions actuelles des présentes Conditions d’utilisation et de la Politique de confidentialité sont publiées sur le site osmium.im, et ce sont les versions qui y sont publiées qui s’appliquent. L’application les lit lorsque vous ouvrez le document depuis « À propos » et conserve la copie qu’elle a lue afin que vous puissiez la relire sans connexion. Si la récupération échoue, l’application affiche un message d’échec avec un lien vers le site web.

Notifications de sauvegarde et vérification : les sauvegardes automatiques peuvent publier une notification locale avec le résultat. Elle peut être désactivée et peut aussi être retardée ou supprimée par le système et par les politiques de batterie : une notification est un confort, pas une preuve qu’une sauvegarde a eu lieu. La page de sauvegarde automatique permet de modifier le mot de passe de sauvegarde ; gardez donc « vérifier avant d’ouvrir depuis une notification » (activé par défaut) ou « vérifier à l’ouverture » activé : si les deux sont désactivés, toute personne ayant votre appareil déverrouillé peut atteindre cette page depuis la notification et modifier le mot de passe.
